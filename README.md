# Мой кошелёк · версия 8 (семейные профили, категории, вклады)

Личное независимое PWA для учёта доходов и расходов. Визуальная структура главной страницы адаптирована по присланному скриншоту Spendee: денежный поток за месяц, столбцы за шесть месяцев, история по дням, поиск сверху, пять нижних вкладок и крупная кнопка «+». **Это не официальный Spendee, не копия его исходного кода и не банковское приложение.**

## Что умеет

- Главная: выбранный месяц, доходы, расходы, разница, интерактивный график за полгода, последние операции по датам, расходы за сегодня.
- Переключение месяца стрелками или нажатием на столбец графика. Кнопка «Этот месяц» возвращает к текущему.
- Нижние вкладки: **Главная · Счета · Обзор · Бюджеты · Больше**.
- Поиск операций сверху; фильтры истории по типу, категории, датам и сумме.
- Нажатие на операцию открывает редактирование; кнопка **+** предлагает доход, расход, скриншот или перевод.
- Доходы, расходы, переводы в той же валюте, категории, кошельки и лимиты.
- OCR скриншотов одной банковской операции на бесплатной библиотеке Tesseract.js (русский + английский). Распознанные данные **проверяются пользователем перед единственным сохранением записи**. Поддерживаются JPG, PNG, WEBP; после первого обращения OCR скачивается из стороннего CDN и требует интернета. Точность не гарантируется.
- Импорт CSV из Spendee, экспорт CSV, локальная резервная копия/восстановление JSON.
- Интерфейс PWA кэшируется для офлайн-открытия. Операции хранятся в IndexedDB на устройстве.

## Как получить свою историю из отдельного файла

Вместе с этим ZIP может распространяться отдельный файл **`moy-koshelek-lichnaya-istoriya-Spendee.json`**. Он содержит операции из присланного CSV, категории (включая сохранённые из HTML имена и цвета) и один счёт «Кошелёк Наличные». Значения положительных сумм считаются **доходами**, отрицательных — **расходами**, как согласовано с пользователем. Валюта — RUB.

1. Откройте работающий сайт «Мой кошелёк».
2. Вкладка **Больше → Импортировать мои данные → Выбрать файл**.
3. Выберите указанный отдельный JSON-файл с телефона.
4. Подтвердите полную замену текущей базы. После восстановления на главной появится история операций по месяцам.

**Внимание:** восстановление **удаляет текущие операции** из локальной базы и заменяет их содержимым файла. Если в новой PWA уже ведутся расходы, сначала сохраните копию текущей базы JSON. **ЛИЧНЫЙ JSON НЕЛЬЗЯ ПУБЛИКОВАТЬ**: он не включён в папку сайта и должен остаться приватным. В CSV нет заметок, подробных счетов и переводов; восстановить их из него невозможно.

Вкладка **Счета** показывает математический баланс по внесённым операциям. **Это не банковский остаток**, поскольку в Spendee много лет учитывались преимущественно доходы. Для корректного остатка в дальнейшем требуется учёт всех расходов и/или калибровка начального остатка.

## Запуск и установка на телефон

Содержимое **папки `moy-koshelek-pwa`** из ZIP нужно выложить на собственный HTTPS-сайт (например, бесплатный статический хостинг). Личный файл JSON на сервер не загружать.

- Компьютер для локального теста: запустите `python -m http.server 8000` из папки `moy-koshelek-pwa`, откройте `http://localhost:8000`.
- Телефон: откройте HTTPS-адрес сайта в Safari или Chrome и выберите «На экран Домой» / «Установить приложение».
- Простое открытие `index.html` через «Файлы» не запускает PWA в штатном режиме: для service worker нужен HTTPS или `localhost`.

## Ограничения и сохранность

- **Синхронизация выключена по умолчанию.** В разделе «Семейный аккаунт» её можно включить после входа. Регулярно делайте резервные копии JSON.
- **OCR — вспомогательная функция**, ошибки в суммах, датах или магазинах возможны; проверяйте перед сохранением. Скриншот после распознавания не сохраняется в историю или JSON.
- Нет прямого подключения к банку, фонового доступа к его операциям, автоматического определения дубликатов между разными источниками со 100% точностью, денежных переводов между разными валютами или конвертации.
- Файлы и база не зашифрованы, поэтому важно защищать устройство и резервные копии.
- Бесплатный OCR работает в браузере; при первом запуске нужен интернет для CDN и языковых моделей, дальнейшая доступность может зависеть от браузерного кэша.
- Исходный код JavaScript и стили доступны для редактирования без сборки и подписок.

## Проверка

Проверены синтаксис JS, шаблоны страниц на данных из CSV, помесячные расчёты и комплектность архива. В этой среде Chromium блокирует навигацию системной политикой, поэтому **визуальное тестирование в браузере и iOS-тестирование пока не выполнены**.


## Автоматический кешбэк по скриншотам Т‑Банка (версия 6)

При распознавании деталей одной банковской покупки PWA отдельно пытается найти сумму списания (например, `−1 171,41 ₽`) и подписанный плюс под ней (`+58 ₽` в тёмной плашке Т‑Банка). Записывает полную стоимость `1 171,41 ₽`, предполагаемый кешбэк `58 ₽` и расход за вычетом кешбэка `1 113,41 ₽`. Выгода включается в статистику **сразу в дату покупки**. Больше не нужно выбирать «Ожидается / Получен» или дату получения кешбэка.

В форме можно вручную изменить сумму кешбэка либо процент, если OCR ошибся; перед единственным сохранением записи проверяйте цифры. Для разных банков OCR ищет явные слова «кешбэк», `cashback` и знак `+` около основного списания. Если маленькую плашку T-Банка OCR не прочитал, приложение попробует один дополнительный распознавательный проход с контрастной обработкой этой плашки. При неудаче кешбэк не угадывается: поле остаётся нулевым, и приложение попросит проверить сумму. Нет платного API.

Баланс в разделе «Счета» отражает **полное списание с карты**, а в статистике отображается **чистый расход**. Это разные показатели; пока возврат не поступил, он не может менять фактический остаток на карте. Для старых записей со статусом «Получен» сохранена обратная совместимость, ранее начисленный кешбэк в балансе учитывается, но выбор статуса убран.

Для обновления на GitHub Pages замените только файлы сайта; личный JSON со Spendee никуда не публиковать. Перед обновлением на всякий случай скачайте полную резервную копию на телефон.


## Исправление импорта (версия 7)

Теперь в разделе «Больше» есть **одно** поле «Импортировать мои данные»: JSON-полная копия автоматически восстанавливает историю после предупреждения о замене, JSON-массив добавляет категории, CSV открывает мастер импорта. Ошибка «Неправильный список категорий» при выборе полной базы больше не возникает. Сначала сохраните резервную копию, если уже вносили новые операции.

Файл `moy-koshelek-lichnaya-istoriya-Spendee.json` с 11 905 операциями корректен, в файлы сайта не включён. В проекте не используйте «Удалить данные сайта» для обновления: потеряете текущую локальную историю. Service Worker обновлён до v7 для перехода с более ранних версий.


## Версия 8 · выбор категорий как в Spendee

Кнопка **+** открывает окно с иконками категорий, тремя вкладками **Расходы / Доходы / Перевод**, и поиском прямо в окне. Порядок категорий — по числу операций с этой категорией **за всю историю** (от большей частоты к меньшей), без привязки к выбранному месяцу. После выбора категории открывается форма суммы, даты, счёта и заметки. Для категорий вида «ВК ...» используем значок человека; прочие иконки назначаются автоматически по названию, без копирования чужой графики.

## Семья: кому принадлежит расход и кто оплатил

Вверху появились **Мой / Жены / Семья**. У каждой новой операции есть два разных поля:

- **Чей доход / расход** — в чей личный бюджет идёт операция;
- **Оплачено с карты / счёта** — чьим банковским счётом фактически платили.

Если оплатили личную покупку картой супруги, личный расход попадает в твой бюджет, а реальные деньги списываются с её счёта. В семейном обзоре покупка учитывается **один раз**, а переводы между своими счетами не становятся доходом или расходом. Старые операции без владельца относятся к **«Мой»**; все 11 905 импортированных операций Spendee остаются на месте. Данные различных валют не пересчитываются по курсу; при просмотре сводок используется валюта выбранного счёта.

Твоя тема — **тёмная**, жены — **светлая розовая**. На её устройстве в «Больше» нужно указать **Чей это телефон по умолчанию → Жены**. В режиме «Семья» используется тема владельца текущего устройства.

**По умолчанию это локальные профили.** Для двух телефонов включите семейную синхронизацию. Не публикуйте финансовые данные в репозитории. Перед обновлением сохраняйте JSON-копию.

## Вклады

«Счета» → **+ Вклад**: можно внести банк, название, владельца, валюту, дату открытия и окончания, годовую ставку и уже имеющийся остаток. Вклад сохраняется как отдельный счёт. Его начальная сумма **не доход**. При пополнении за счёт банковской карты сделайте **Перевод** между счетами, а не запись «Доход».

«Счета» → **+ Начисление процентов**: появляется операция **дохода по категории «Проценты по вкладам»**. Выберите, куда реально поступили проценты: на сам вклад или другую карту в той же валюте. Если процент уже импортирован из банка как доход, второй раз его не добавляйте.

Для старых и действующих вкладов доступен **CSV-импорт списка**. Кнопка **Скачать шаблон CSV** выдаёт пример с колонками:

`Банк;Название;Владелец;Дата открытия;Сумма;Ставка %;Дата окончания;Статус`

Это простой формат для списка вкладов, не автоматическое подключение к банку и не универсальный импорт любой банковской выписки. Поле «Сумма» означает уже существующий остаток на вкладе (он **не прибавляется к доходам**). Если баланс банковской карты уже содержит ту же сумму, скорректируйте счета, чтобы не было двойного учёта. Архивные/закрытые вклады помечаются как исторические.

## Обновление GitHub Pages

1. Сохраните резервную копию JSON в текущем приложении: **Больше → Скачать полную копию JSON**.
2. Распакуйте ZIP и загрузите **содержимое** папки `moy-koshelek-pwa` в корень репозитория `medvedevpa/moy-koshelek`, заменив предыдущие файлы.
3. После **Commit changes** и завершения GitHub Pages откройте `https://medvedevpa.github.io/moy-koshelek/`. Возможно, потребуется полностью закрыть и заново открыть PWA для обновления Service Worker.
4. **Не удаляйте приложение и не очищайте данные сайта**, если не сохранили резервную копию. Не публикуйте личную историю или данные банков на GitHub.

Синтаксис JavaScript и основные расчёты проверены автономными тестами. Полноценное тестирование браузерного интерфейса/устройства iPhone в этой среде заблокировано политикой браузера, поэтому после публикации необходимо проверить интерфейс на телефоне.


## Семейная синхронизация (v10)

«Больше → Семейный аккаунт». После входа (если семья одна, она выбирается автоматически) отображается **«Не синхронизируется»**, пока не выполнено первое подключение. Нажмите **«Включить синхронизацию»** на основном телефоне и подтвердите отправку его текущей базы. В облаке хранится семейная копия. На втором устройстве войдите в тот же семейный аккаунт и нажмите ту же кнопку: если в облаке уже есть записи, приложение предложит скачать их, предупредив о замене местной базы.

**Перед подключением всегда экспортируйте JSON.** Обязательно подключайте основное устройство первым — второе не должно случайно загрузить пустую базу. История Spendee остаётся только на основном телефоне до явного подтверждения загрузки. Не публикуйте JSON с транзакциями в GitHub.

После первого подключения операции передаются автоматически при доступном интернете, и приложение проверяет изменения приблизительно каждые 30 секунд, когда открыто. Синхронизация требует входа и присоединения к одной семье; просто вход в аккаунт без подключения не передаёт операции. Встроенная авторизация не гарантирует фонового обмена, когда приложение закрыто на iOS. Проверяйте статус подключения и результаты отправки.

**Технические ограничения:** пилотная синхронизация; автоматическое разрешение конфликтов отсутствует. При сетевом сбое операции остаются локально и в очереди. При попытке записать устаревшую ревизию сервер возвращает конфликт, чтобы не затирать изменения. Вложения и изображения скриншотов не синхронизируются, только текстовые поля. Не очищайте локальные данные без резервной копии. Для доступа к серверу используется публичный ключ и авторизация RLS, никогда не кладите секретные ключи в сайт.
