# Мой кошелёк — v13 Family Design

Это PWA для мобильного телефона с интерфейсом в стиле семейного бренда «Мимишка». Приложение можно установить с GitHub Pages, оно продолжает использовать ту же локальную базу IndexedDB, что и версии v9–v12, и то же подключение к семейной облачной базе. Отдельные финансовые данные в архив не включены.

## Как обновить текущий сайт

1. **Сначала на основном телефоне сделайте JSON-резервную копию**: «Больше» → «Скачать полную копию JSON». Сохраните её вне браузера, например в «Файлах» iPhone или на компьютере.
2. Распакуйте ZIP. На GitHub в репозитории `moy-koshelek` замените **содержимое** папки `moy-koshelek-pwa` — `index.html`, JavaScript, CSS, `sw.js`, `manifest.webmanifest` и обе папки `assets` и `icons`. Не загружайте внешнюю папку как дополнительный уровень.
3. После `Commit changes` дождитесь завершения GitHub Pages. Откройте `https://medvedevpa.github.io/moy-koshelek/` в Safari. Если остался предыдущий интерфейс, обновите вкладку или перезапустите приложение. **Не очищайте данные сайта и не удаляйте установленное приложение** ради обновления.
4. Войдите в семейный аккаунт, если потребуется. Синхронизацию при активном состоянии можно запустить вручную в «Больше» → «Семейный аккаунт» → «Обновить данные».

**Важно:** заменяйте **все файлы** из версии v13, в том числе новый `premium.css`. Если его забыть, новый экран будет выглядеть неправильно.

## Четыре профиля

- **Мой**: глубокая графитовая, золотая и изумрудная тема.
- **Жены**: светло-розовая и золотая тема.
- **Матвей**: аква/мята; отдельная «Копилка Матвея», плановые ежемесячные расходы и возможность назначать вклады.
- **Семья**: салатовая/мятная тема, объединённые операции и счета.

Переключатель меняет **представление** данных, не создавая отдельный вход. Ребёнку не нужна своя учётная запись: родители назначают владельца его операций и счетов. Старые импортированные операции без владельца остаются в разделе «Мой», как было раньше.

## Актуализация остатков после истории Spendee

Зайдите в **Счета → Актуализировать остатки**. Введите фактические остатки на каждой карте, наличными и на вкладах, затем сохраните. В каждой записи счёта сохраняется контрольная точка — сумма, календарная дата и время.

До контрольной точки старые операции **не пересчитывают** актуальный баланс, но остаются в истории, аналитике и отчётах. Операции, добавленные позже, продолжают менять остаток. Корректировка **не записывается доходом или расходом** и синхронизируется как изменение счёта. При настройке сверяйте каждый вклад и накопительный счёт: если одна и та же сумма физически содержится в двух счетах, общий баланс задвоится.

Если вы добавите исправление к уже учтённой операции в тот же день, контролируйте реальный остаток отдельно: при использовании контрольной точки исторические операции этого дня, созданные до неё, уже не будут влиять на текущий баланс.

## «Наш дом»

«Наш дом» теперь отдельная вкладка. Для нового расхода откройте страницу дома и нажмите **«Добавить расход по дому»** — выберите категорию и сумму, при этом опция «Отнести к проекту „Наш дом“» будет отмечена автоматически. Можно выбрать раздел: материалы, работы, ипотека, содержание, прочее. Эта же опция доступна в подробностях любой расходной операции.

В **«Настроить»** можно указать ориентировочный бюджет стройки, плановый ежемесячный платёж по ипотеке и остаток ипотечного долга. Это **плановые показатели**; они не создают банковских списаний, пока не записать реальный расход. Исторические операции не будут автоматически относиться к дому по одной лишь категории «Дом» — так не смешаются строительство и бытовые расходы. При необходимости старую операцию можно открыть и отметить вручную.

**Учёт ипотеки упрощён до денежного потока:** в расходы попадает сумма платежа. Для бухгалтерского разделения процентов и погашения основного долга понадобится отдельная доработка.

Эскиз дома из вложения помещён в `assets/our-house.webp`. Поскольку сайт размещён на **публичном** GitHub Pages, изображение дома будет публично доступно. При желании его можно заменить локально или убрать. Внутри ZIP нет банковских выписок, CSV/JSON Spendee, паролей, секретных токенов и персональных транзакций.

## Остальная функциональность

- выбор доходной или расходной категории, с поиском и сортировкой по числу записей за всю историю;
- быстрый ввод суммы на собственной цифровой клавиатуре;
- расходы с суммой и процентом кешбэка, статистика чистой траты;
- OCR по банковским скриншотам, с ручной проверкой;
- импорт CSV, импорт JSON, экспорт CSV и JSON;
- разные карты/вклады, пополнение процентами, импорт списка вкладов из CSV;
- личные и семейные обзоры, бюджетные лимиты в разделе «Больше»;
- бесплатная синхронизация между устройствами, если семейное подключение уже настроено.

## Ограничения и честные предупреждения

- Это **веб-приложение**, не нативное приложение банка. Автоматическое подключение к банковским счетам отсутствует.
- Распознавание изображений по-прежнему зависит от размера и качества скриншота, библиотека OCR подгружается из интернета.
- Cloud-API зависит от доступности удалённой базы. Локальная история остаётся важной, регулярно делайте резервную копию JSON.
- На iPhone приложение хранит пользовательские данные в локальном хранилище сайта; удаление данных сайта может удалить локальные изменения, которые ещё не ушли в облако.
- Включённый RLS ограничивает доступ к семейным записям участниками семьи, однако жизненный цикл сессий и конфликтов двух устройств нужно проверить на ваших реальных аккаунтах. Серверные правила, функции авторизации и URL в `cloud.js` в этой сборке не изменялись.
- Дизайн повторяет наши концепты по композиции, цвету, брендингу и типографике. Некоторые глянцевые 3D-поверхности из иллюстративных макетов реализованы CSS-эффектами вместо тяжёлых изображений, чтобы сохранить скорость на телефоне.

## Для разработчика

Статическое приложение ES Modules без сборщика. Основной интерфейс — `app.js`; данные IndexedDB — `db.js`; облачный обмен — `cloud.js`; импортер — `data-import.js`/`import.js`; OCR — `ocr.js`; основной стиль — `style.css`, новый слой дизайна — `premium.css`. Ресурсы — папка `assets/`; Service Worker — `sw.js`.

Новые поля данных: `wallet.balanceAnchorMinor`, `balanceAnchorDate`, `balanceAnchorAt`; `transaction.projectId`, `houseSection`; `budget.kind === 'houseProject' | 'recurring'`. Они необязательные, поэтому старые записи остаются валидными. Эти поля JSON-совместимы и синхронизируются существующим механизмом семейного обмена как часть записей.
